anchor is a static site generator for AsciiDoc. It is written in Common Lisp
and built on cl-adoc.

The build operates on documents, not on strings. cl-adoc parses a document
into a tree. anchor uses the tree. Titles, dates, excerpts, headings, and link
targets come from the parsed document. They are not recovered from rendered
HTML. They are not repeated in front matter.

This gives anchor several rules:

* No front matter. The document is the metadata.
* No excerpt marker. An excerpt is a subtree.
* No regex pass over rendered output. References are resolved on nodes before
  rendering.
* Link and image checks walk the document tree. They do not parse rendered
  HTML.

The second rule is thinness. anchor should be readable in an afternoon. When a
convention can replace a feature, the convention wins.

== The shape of a site

The filesystem is the data model. A directory with `index.adoc` is a page. Its
path is its URL. There is no permalink configuration and no slug field.

----
mysite/
  _anchor.lisp
  index.adoc                    ->  /
  about/index.adoc              ->  /about/
  posts/
    index.adoc                  ->  /posts/
    2026/anchor-design/
      index.adoc                ->  /posts/2026/anchor-design/
      pipeline.svg                  media, colocated with the page
  style.css
----

A section is therefore a first-class object without configuration. `posts/` is
both a page and the parent of pages. Nothing declares that relationship.

A file or directory whose name starts with `_` is reserved and is not written
to the output. `_anchor.lisp` configures its directory and everything below
it. Configuration is merged parent to child.

`_media/` holds assets shared by a subtree. Referenced files inside `_media/`
are copied.

A file or directory whose name starts with `.` is hidden. It belongs to
another tool, such as `.git/` or `.DS_Store`, and anchor ignores it.

== Using it

----
anchor build [DIR] [--output DIR] [--drafts] [--force]
anchor serve [DIR] [--output DIR] [--port N]
anchor check [DIR] [--drafts]
----

`build` writes the site to `_site/`.

`check` reports missing references, unused files, duplicate content, page
weight, and reference resolutions. It exits non-zero when something is wrong.
That is what CI reads.

`serve` builds, serves, includes drafts, and rebuilds when the source changes.

`serve` keeps the site graph in the Lisp image:

[source,lisp]
----
(anchor:serve "mysite")

(anchor:page "posts/2026/anchor-design")   ; the page object
(anchor:rebuild-page "posts/2026/anchor-design")
----

Recompile a layout at the REPL and the next request uses it. This is not a
hot-reload feature. It is what having an image gives you.

== Layouts

A layout is a function from a page and a site to an HTML tree as
s-expressions. There is no template language. Common Lisp is the template
language.

[source,lisp]
----
(defun article (page site)
  (declare (ignore site))
  `(:article
    (:h1 ,(anchor:page-title page))
    (:p :class "meta"
        (:time :datetime ,(anchor:page-date page)
               ,(anchor:page-date-human page)))
    (:raw ,(anchor:page-body-html page))))
----

`(:raw ...)` inserts rendered HTML without escaping. It is the only escape
hatch.

Layouts are selected by the `:layout` key. They inherit through the same
cascade as every other configuration value.

Emitters and head tags are ordinary lists of ordinary functions. The Atom
feed, `sitemap.xml`, `robots.txt`, and `/tags/` page are functions in
`anchor:*emitters*`. A site that wants a fifth emitter writes one.

== What it does not do

anchor has no plugin system, theme format, asset pipeline, image processing,
shortcodes, or deployment step.

A theme is a CSS file and, optionally, a layout function. anchor produces a
directory. rsync, git, or CI can put that directory on a host.

SPEC.adoc lists the full scope and the reasoning behind it. Each section is
marked as shipped in 1.0, deferred, or refused. It is the contract, and anchor
keeps it honest by rendering its own specification.

== Building it

----
make test    # run the test suite
make bin     # dump an executable into the project root
make repl    # load the system into a REPL
----

anchor needs SBCL and ocicl. It is built and tested against the SBCL versions
packaged by Ubuntu 24.04 and 26.04: 2.2.9 and 2.6.0. Other implementations are
untested, not unsupported.

Dependencies come from ocicl, at the digests pinned in `ocicl.csv`:

----
ocicl install
----

anchor needs cl-adoc 0.2.0 or later for description lists.

== A note on trust

anchor loads and evaluates `_anchor.lisp` from the source tree. This lets a
site define its own layout functions.

It also means the source tree is assumed to be yours. anchor is not a sandbox
and does not try to be one.

== Stability

anchor is finished.

That does not mean abandoned. The scope was finite and written down before the
code existed: every section SPEC.adoc marks `v1`, and nothing else. All of
those sections shipped in 1.0, so the freeze is now in force.

anchor takes bug fixes and changes required to track cl-adoc's released
interface. The Lisp interface is settled on the same terms.

Sections marked `later` are not promises. Sections marked `non-goal` are
permanent.

A tool that does a known amount and then stops is the point, not a compromise.
